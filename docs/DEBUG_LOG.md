### BUG-001 ｜ 2026-10-29 ｜ 全国地图能出来但所有省份都不上色

- **现象（怎么错的）**：地图轮廓和边界正常显示，但所有省份都是同一种深色，鼠标悬停也没有数据显示。
- **根因（为什么错）**：`/api/map-data` 返回的字段是 `province`，而 ECharts 的 `map` 系列按 `name` 匹配行政区。数据里没有 `name`，所以一个省份都没匹配上，全部走了默认 `itemStyle.areaColor`。
- **解决（改了什么）**：前端取到数据后补一层映射：
  ```js
  const data = (res.data || []).map(d => Object.assign({}, d, { name: d.province }));
  ```
- **预防（下次怎么不踩）**：用 ECharts 地图时，先确认数据里 `name` 和 GeoJSON 的 `properties.name` 完全一致；接口字段名不要直接假设，先打印一条看结构。

### BUG-002 ｜ 2026-10-29 ｜ 带 `?province=广东省` 打开时，顶部显示已下钻但数据还是全国的

- **现象（怎么错的）**：地址栏加省份参数打开页面，右上角显示“当前分析下钻域：广东省”，但指标卡仍是 33,652 座，城市 TOP10 还是上海、北京。
- **根因（为什么错）**：`DOMContentLoaded` 里并发发起了一堆 `fetch`，初始化请求和 `setFilterProvince()` 触发的请求同时在跑，全国的响应后到，把下钻结果覆盖了。
- **解决（改了什么）**：初始化改成 `async` 顺序执行，等初始图表都渲染完，再读取 URL 参数并调用 `setFilterProvince()`。
- **预防（下次怎么不踩）**：带默认参数的页面，先完成初始渲染再应用参数；异步初始化时不要既发请求又不等待。

### BUG-003 ｜ 2026-10-29 ｜ 充电费解析失败率约 80%

- **现象（怎么错的）**：清洗后 `electricity_price` 只有不到 20% 能解析出数字，其余都要用中位数填充，电费区间分布图明显失真。
- **根因（为什么错）**：原始数据里费用字段有 5 种写法：`电费:00:00~06:00:0.45,...`、`00:00-06:00:0.8200;...`、`时间段:...,电价:0.500`、`0.2775-1.0574元/度`、单一数字 `1.20`。第一版正则只匹配了第一种。
- **解决（改了什么）**：`parse_avg_price()` 按顺序尝试四种提取方式（时间区间价格、`电价/服务费` 标签、价格区间取中点、单值），解析不出的“不详/未设置”按缺失处理。
- **预防（下次怎么不踩）**：拿到文本型字段先 `value_counts` 看看有几种格式，再写解析；解析完统计缺失率，超过 10% 就说明规则没覆盖全。

### BUG-004 ｜ 2026-10-29 ｜ 电费出现 0 元和 5 元/度的异常值

- **现象（怎么错的）**：`MIN(electricity_price)=0`、`MAX=5`，电费区间图最右边多出一档“1.2 元以上”的孤立柱子。
- **根因（为什么错）**：个别站点把“停车费”或错误文本混进了充电费字段，解析出了 0 或 5 这类不合业务常识的数值。
- **解决（改了什么）**：清洗时把 `<= 0` 或 `> 3` 元/度的值视为异常置空，再用同省中位数填充，共处理 889 条。
- **预防（下次怎么不踩）**：入库前对连续型字段做上下界检查，业务上不可能的值要单独统计并记录，不要直接放过。

### BUG-005 ｜ 2026-10-29 ｜ 启动服务报端口被占用，页面打开还是旧版本

- **现象（怎么错的）**：新版 `server.py` 启动后访问 8080，返回的还是旧接口数据；`netstat` 看到多个进程同时监听 8080。
- **根因（为什么错）**：之前调试留下的几个 Python 进程没有退出，Windows 下 `SO_REUSEADDR` 允许多个进程绑定同一端口，先启动的进程接管了连接。
- **解决（改了什么）**：用 `netstat -ano | findstr :8080` 找到 PID，逐个结束旧进程，再启动新服务。
- **预防（下次怎么不踩）**：启动前先检查端口占用；调试脚本里加 `finally` 关闭服务，不要把进程留在后台。

### BUG-006 ｜ 2026-10-29 ｜ `/favicon.ico` 返回 500

- **现象（怎么错的）**：浏览器控制台报 `favicon.ico 500`，Flask 日志里显示 404 被转成了 500。
- **根因（为什么错）**：`server.py` 里注册了全局 `@app.errorhandler(Exception)`，把所有异常（包括 404）都包装成 500 JSON。
- **解决（改了什么）**：增加 `/favicon.ico` 路由直接返回 204；保留全局异常处理，但明确它是给接口用的。
- **预防（下次怎么不踩）**：全局异常处理不要吞掉 HTTP 状态码；静态资源类请求单独给路由。

### BUG-007 ｜ 2026-10-29 ｜ 截图不是 1920×1080，底部明细表被截掉

- **现象（怎么错的）**：Selenium 设置 `--window-size=1920,1080` 后截图仍为 1902×928，页面底部表格只露出几行。
- **根因（为什么错）**：窗口尺寸包含浏览器边框和地址栏，实际视口小于 1920×1080；页面内容高度超过视口，底部被裁。
- **解决（改了什么）**：截图脚本用 CDP 把视口锁定为 1920×1080：
  ```python
  driver.execute_cdp_cmd("Emulation.setDeviceMetricsOverride",
      {"width": 1920, "height": 1080, "deviceScaleFactor": 1, "mobile": False})
  ```
  同时页面改成 1920×1080 固定画布整体缩放，保证一屏完整。
- **预防（下次怎么不踩）**：大屏项目先定死设计分辨率，再在截图端锁定同样的视口，不要依赖窗口尺寸。
